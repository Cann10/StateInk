# 3分デモ動画 操作手順

## 撮影前（動画外）

- 画面幅1280px以上、ブラウザ倍率100%にする。
- FrontendとRecognition backendを起動し、Homeを表示する。
- 通知、DevTools、個人情報が映るタブを閉じる。
- 認識デモには、白紙へ黒ペンで状態2〜3個と明確な直線矢印を描いた画像を用意する。
- ConnectionとDirectionは自動完成品質ではないため、Reviewで直す前提で撮影する。

## 0:00–0:25 — 価値を一文で伝える

**画面:** Home

**ナレーション:**

> StateInkは、紙に描いた状態遷移図を下書きにし、実際に動かして設計ミスまで確かめられるアプリです。

メインコピーと3つの入口を映す。ここではまだクリックしない。

## 0:25–1:35 — 問題を見つけ、直し、動かす

1. 「サンプルを試す」をクリックする。
2. 設計チェックの「売り切れ」に入るとどこにも移動できない説明と、再現操作 `coin → select → sold_out` を示す。
3. Simulatorで `coin`、`select`、`sold_out` を順に押し、現在状態が「売り切れ」になることを示す。
4. 遷移追加フォームで移動元「売り切れ」、移動先「待機」、イベント`refund`を設定し、「追加」を押す。
5. 「問題は見つかりませんでした」へ即時に変わることを示す。
6. 「リセット」を押し、`coin → select → sold_out → refund`を実行する。
7. 現在状態が「待機」へ戻ることを示す。

**ナレーション:**

> 問題の説明だけでなく、BFSで最短の再現操作を示します。図を修正すると解析結果も即座に変わり、同じ設計をその場で再実行できます。

## 1:35–2:35 — 紙から下書きを作る

1. Homeへ戻り、「紙から読み取る」をクリックする。
2. 用意した画像を選択する。
3. 「読み取り結果を確認してください」とconfidence表示を示す。
4. 状態名とevent名を短く修正する。
5. low-confidenceの遷移でsource、targetを確認し、必要なら「向きを反転」を押す。
6. 「確認してEditorへ」を押し、イベントボタンで1回遷移させる。

**ナレーション:**

> 認識は自動完成ではありません。構造の下書きを作り、接続と方向を人が確認するHuman-in-the-loop方式です。文字が読めなくても仮名の状態を編集できます。

## 2:35–3:00 — 技術と結論

**画面:** Editor、Simulator、設計チェックが同時に見える位置

**ナレーション:**

> ReactのUIと、状態機械のIR、Simulator、Analyzerを分離しています。最短反例にはBFS、終了できない循環の解析にはTarjan法、画像の下書き生成にはFastAPIとOpenCVを使いました。描くだけで終わらず、動かして確かめられることがStateInkの価値です。

## 撮影時の注意

- 外部評価値を映す場合はSupported subsetのState 94.9%、Transition 95.2%、Connection 50.0%、Direction 29.4%を併記する。
- 「写真から完全自動で完成する」「高精度に矢印方向を認識する」とは説明しない。
- 認識が崩れた場合も隠さず、Reviewで直せる設計を見せる。
